# Decisions — Portfolio

- 2026-07-24: Start as a static Astro site with content collections only; revisit CMS and integrations after requirements are defined.
- 2026-07-24: Keep the portfolio intentionally unconstrained: no initial palette, typography, visual system, project taxonomy, or single-medium assumption. Develop the visual direction incrementally from real work.
- 2026-07-25: Use Astro 7 as the initial portfolio shell. "Static" describes the default delivery of the shell, not a restriction on individual projects; interactive routes may use substantial client-side JavaScript or on-demand server features.
- 2026-07-25: Keep portfolio content repository-authored and do not add TinaCMS or another CMS. TinaCMS solved a multi-editor requirement for First Known Use that does not exist here.
- 2026-07-25: Permit p5.js, Canvas, WebGL/WebGPU, Web Audio, framework islands, games, and other experimental runtimes without a site-wide JavaScript cap. Isolate them by route or component, preserve accessible context and fallbacks, and split unusually large experiences into separate applications when justified.
- 2026-07-25: Defer Cloudflare Workers bindings, persistence, authentication, WebSockets, and Durable Objects until a specific experiment needs server state or multiplayer coordination.
- 2026-07-25: Centralize Codex decision rules in the nearest `AGENTS.md`. Load shared guidance once per session, search project memory by task topic, keep role guides delta-only, and use change-type validation gates to improve lower-model reliability without repeatedly loading unrelated context.
- 2026-07-25: Start the portfolio with a paired First Known Use slice: a semantic project context route plus an isolated native-JavaScript word-field artifact. Keep the artifact dependency-free and reversible so a later p5.js, Canvas, GPU, audio, or separate-application treatment can replace it without coupling the portfolio shell to that runtime.
- 2026-07-25: Use self-hosted JetBrains Mono and the Earthsong kitty palette for the current portfolio exploration. This is an explicitly approved, reversible visual direction for the evolving shell, not a permanent identity or constraint on future project-specific presentations.
- 2026-07-25: Organize the portfolio into independently authored route sections—initially web development, audio, networking, and fabrication—with room for additional sections. Section directories may diverge in layout, content model, styling, and runtime so ambitious web-development changes do not affect unrelated work.
- 2026-07-25: Keep the web-development preview-to-case-study navigation as a normal anchor with an optional named Astro shared-element transition. Defer more experimental portal/click interception until a future interaction can be prototyped and verified separately.
- 2026-07-25: Treat the interactive word field as a web-development section experiment, not part of the First Known Use case study. Keep its runtime and styles inside `src/sections/web-development/`.
- 2026-07-25: Use a live cross-origin iframe of `firstknownuse.com` for the web-development preview window because the site permits framing. Review deployments may inform the portfolio copy, but the canonical project domain remains the visitor-facing destination; keep the local asset as the durable case-study visual if the external preview later becomes unavailable.
- 2026-07-28: Present Proof Sheet as a self-contained web-development experiment. Describe its client-side inference, Canvas, worker, WebGPU/WASM, and deterministic fallback behavior in the portfolio without importing its dependencies or runtime into the portfolio shell.
- 2026-07-28: Embed a dependency-free Proof Sheet working slice in the portfolio route. Keep the artifact local-only and deterministic while the full project’s model-backed runtime remains independently deployable and isolated.
- 2026-07-28: Use the documented `Xenova/detr-resnet-50` browser model instead of OWLv2 for the embedded Proof Sheet detector. Load Transformers.js from a module worker via the browser CDN to avoid bundling its Node-oriented `sharp` and `onnxruntime-node` dependencies into the static portfolio; retain WebGPU/WASM and deterministic fallback paths.
- 2026-07-28: Configure the Proof Sheet worker with an explicit matching `onnxruntime-web` WASM asset path and probe `requestAdapter()` before selecting WebGPU, so browsers without an available GPU reach the functional WASM detector instead of the geometry fallback.
- 2026-07-28: Supersede the earlier embedded detector choice with the current standalone Proof Sheet architecture: OWLv2 is the sole detector, loaded from the browser CDN in an isolated worker; local ONNX WASM assets, grain, and the font package are build assets, while model weights are disclosed as remote first-use downloads. Detector boxes use a source-image pixel contract and deterministic geometry is labeled as unconfirmed fallback output.
- 2026-07-29: Contain Proof Sheet and Input Sigil within `/work/web-development/provenance/`, a dedicated browser-research archive. Keep the portfolio shell and web-development index clear, client- and hiring-legible surfaces; PROVENANCE is an authored branch of the practice rather than its sitewide identity. Preserve former specimen URLs as permanent redirects.
- 2026-07-29: Add a public `/contact/` page with direct email, phone, and GitHub links. Use security-career material only to author a capability and learning page for Networking; never publish private resumes, job strategy, address, salary information, or opportunity-specific application documents.
- 2026-07-29: The portfolio carries Montana Stake as its name and practice description in metadata, but assigns no single job title. Client work, security employment, collaboration, and the SPEC's cross-discipline requirement make a fixed title inaccurate; the work sections provide the relevant labeling for each audience.
